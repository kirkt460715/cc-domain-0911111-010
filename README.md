# Meterbook 数据用量结算

对双边数据使用记录进行核对、费率计算、争议处理、调整结算和成本分配。金额使用十进制字符串，时间使用明确的 UTC 偏移；完整性摘要不提供外部身份认证。

## 用量预测实验

除已发生费用外，Meterbook 支持可保存的用量预测实验，用于在季度结束前识别可能超预算的项目。

* 按计量项预测知识截止（`cutoff_at`）前已经核对、且双方头部事件均已到达的日用量；没有证据的日历日记为“数据没到齐”（缺失），核对数量恰为零的日记为明确的零消费，二者不会互相混淆。
* 每个实验冻结自己的费率表，多计量项始终按费率阶梯所需的费率区间粒度结算，绝不先平均单价。
* 内置三个候选模型：最近值、同星期季节朴素法和指数平滑。所有参数只由对应训练窗口决定（平滑系数在固定网格上按窗口内 SSE 选取），滚动起点回测按预测跨度给出分跨度 MAE，并用历史残差构造经验分位数区间及实测覆盖率。
* 历史不足或观测全零时显式降级（`insufficient_history`、`all_zero_history`），并给出预算触达日期的最早/最晚区间与候选模型选择依据（最低整体回测 MAE 及并列顺序）。
* 迟到用量修正通过 `forecast.revise` 另建实验，可改变预测并与旧版比较；换费率通过 `forecast.reprice` 另建实验，只重新换算费用、不暗中重训（结果含 `retrained:false`）。
* `forecast.lineage` 可查到每个训练/回测窗口实际可见的知识版本（各核对运行的修订、摘要与已知用量标识）。


## 运行环境

使用 Python 3.11，核心功能依赖标准库和 SQLite。演示和测试只使用本地合成数据，不需要账户、设备或外部运行服务。请从项目根目录执行命令。

## 检查与运行

构建检查验证语法，测试使用临时数据目录，不会连接远端服务。

```sh
python3 -m compileall -q meterbook
python3 -m unittest discover -s tests -v
python3 -m meterbook replay fixtures/settlement.json
```

演示会展示产品的实际数据处理和输出，运行结束自行退出。查看现有接口：

```sh
python3 -m meterbook capabilities
```

## 目录与数据

meterbook/ 保存领域逻辑和请求入口，tests/ 包含正常行为、边界与恢复测试。例子中的标识和记录为合成资料，不包含真实人员或生产测量。业务目录和本地数据库由调用者指定，应与源码分开保存。

## 干净环境复现

容器定义固定运行时版本。构建时准备环境，运行时无需网络；每次启动会复制只读源码到临时工作目录，测试产生的文件不会写回仓库。

```sh
docker build -t local-product-check .
docker run --rm --network none local-product-check
```
